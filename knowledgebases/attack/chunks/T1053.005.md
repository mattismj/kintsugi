The Windows Task Scheduler runs programs and scripts at a set time or in response
to a trigger such as logon, idle, or an event. Adversaries register tasks to gain
execution and persistence, often pointing the task at a script or a copy of a tool
in a user-writable directory. Task definitions live in the registry and in the task
directory, so both can be audited after the fact. A newly registered task whose
action is a shell, a script interpreter, or a file under a temporary or user
profile path is the usual signal.
